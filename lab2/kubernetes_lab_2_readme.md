# Kubernetes Lab 2: Container Runtime Inspection, Service Networking (`iptables`), & Optimistic Concurrency

This lab explores how Kubernetes manages pods and services under the hood inside a **Kind (Kubernetes in Docker)** node (`kind-worker`). You will inspect container runtimes directly with `crictl`, examine `EndpointSlices` and `iptables` NAT rules created by `kube-proxy`, and observe Kubernetes optimistic concurrency control via `resourceVersion`.

---

## Prerequisites

* A running **Kind** cluster (with a worker node container named `kind-worker`, or update `NODE` to match your worker container name, e.g., `klu-worker`)
* `kubectl` configured to point to your cluster
* `docker` CLI available on your host

---

## Step 1: Navigate to Workspace and Recreate the `web` Deployment

1. Navigate to your project directory:
   ```bash
   cd ~/Documents/kuberna
   ```

2. Check existing deployments and pods:
   ```bash
   kubectl get deployments
   kubectl get pods
   ```

3. Scale the deployment, then delete and recreate `web` cleanly with **3 replicas** running `nginx`:
   ```bash
   kubectl scale deployment web --replicas=3
   kubectl delete deployment web
   kubectl create deployment web --image=nginx --replicas=3
   ```

## Step 2: Inspect Pods and Containers Inside the Worker Node (`crictl`)

1. Create a second deployment (`web2`) with 3 replicas:
   ```bash
   kubectl create deployment web2 --image=nginx --replicas=3
   ```

2. Set a shell variable for your Kind worker container name and use `crictl` inside the node to list pod sandboxes and running `nginx` containers:
   ```bash
   NODE="kind-worker"
   docker exec $NODE crictl pods --name web
   docker exec $NODE crictl ps --name nginx
   ```

3. *(Optional)* Inspect a specific pod sandbox's IP address (replace `<POD-ID>` with an ID from the `crictl pods` output) or view recent `kubelet` logs for `web-` pods:
   ```bash
   docker exec $NODE crictl inspectp <POD-ID> | grep '"ip"'
   docker exec $NODE journalctl -u kubelet --no-pager | grep "web-" | tail -n 5
   ```

## Step 3: Expose the Service and Inspect `EndpointSlices` & `iptables` Rules

1. Expose the `web` deployment on port `80` (if `service/web` already exists, delete it first or inspect the existing one):
   ```bash
   kubectl expose deployment web --port=80
   ```

2. Inspect the `ClusterIP` service, its backing `EndpointSlice` pod IPs, and the `iptables` DNAT / load-balancing rules generated by `kube-proxy` inside the node:
   ```bash
   kubectl get service web
   kubectl get endpointslices -l kubernetes.io/service-name=web
   docker exec $NODE iptables-save | grep "default/web"
   ```
   *(Notice how `iptables` uses `--mode random --probability` rules to distribute traffic across the three pod endpoints on port `80`.)*

## Step 4: Test Optimistic Concurrency (`resourceVersion`) & Clean Up Resources

1. Export the live `web` deployment manifest to a local YAML file and inspect its `resourceVersion`:
   ```bash
   kubectl get deployment web -o yaml > web-old.yaml
   grep "resourceVersion" web-old.yaml
   ```

2. Modify the live object in the cluster (which increments its `resourceVersion` on the API server) and then attempt to replace it using the stale `web-old.yaml` manifest:
   ```bash
   kubectl scale deployment web --replicas=3
   kubectl replace -f web-old.yaml
   ```
   *(Kubernetes rejects the request with `Error from server (Conflict): ... the object has been modified; please apply your changes to the latest version and try again`, demonstrating optimistic concurrency control.)*

3. Recreate `service/web` to observe a newly allocated `ClusterIP` and `EndpointSlice`:
   ```bash
   kubectl delete service web
   kubectl expose deployment web --port=80
   kubectl get service web
   kubectl get endpointslices -l kubernetes.io/service-name=web
   docker exec $NODE iptables-save | grep "default/web"
   ```

4. Clean up the `web` service and deployment when finished (running `delete` a second time confirms the resources are completely removed with `NotFound` errors):
   ```bash
   kubectl delete service web
   kubectl delete deployment web
   ```
